# 개발 환경과 실행

로컬 개발 환경의 구성과 실행·테스트 방법입니다.

## 환경 구성

- Python 가상환경을 만들고 저장소의 의존성을 설치합니다.
- 접속 정보(백엔드 API, 검색 엔진, 스토리지, LLM 자격)는 환경 변수 또는 `.env` 파일로
  설정합니다. 키 목록은 [설정 사전](../reference/config.md)을 참고하십시오.
- 페이지 실측을 위해 **Chrome 설치가 필요**합니다. 미설치 상태에서도 실행은 되지만 페이지
  구성 품질이 저하됩니다([외부 의존](../reference/external-services.md) 참조).

## 실행

ASGI 서버로 API 앱을 기동하고 상태 확인 엔드포인트(`/health`)로 기동을 확인합니다.
LLM·검색·백엔드 없이 구조만 확인하려면 **도구 모드를 모의로 설정**해 기동할 수 있습니다.

| 모드 | 설정 | 동작 |
|---|---|---|
| 실제 | `tool_mode=live` | 실제 LLM·검색·스토리지·백엔드 API 사용 |
| 모의 | `tool_mode=mock` | 모의 LLM과 빈 데이터 조회 — 외부 자원 없이 기동 |

## 테스트

**유닛테스트** — `tests/unit`은 **LLM과 외부 자원 없이 실행**됩니다. 테스트 기본 환경이
모의 도구와 빈 데이터 조회로 설정되어 있어 DB 연결이 필요 없습니다. 각 테스트가
고정하는 동작은 [테스트 구성](./testing.md)을 참고하십시오.

**대화 시나리오 러너** — `tests/run_content_scenario.py`는 서버를 실제로 띄워 다단계
대화를 HTTP로 실행하는 검증 도구입니다. **실제 LLM을 호출**하므로 비용과 시간이 들며, 세션
복원 검증을 위해 중간에 서버를 재시작하는 단계를 포함합니다.

**유닛테스트 통과만으로 검증을 끝내지 않습니다** — 요구가 발화·생성·수정까지 실제로
반영되는지는 대화 시나리오로 확인하는 것이 이 프로젝트의 검증 기준입니다.

## 관측

- 모든 LLM 호출의 토큰 사용량이 호출 단위로 로그 파일에 기록됩니다.
- 생성 중간 산출물 덤프 설정을 켜면 교시별 파이프라인 중간 결과가 파일로 남습니다.
- 자세한 진단 방법은 [진단과 관측](./diagnosis.md)을 참고하십시오.
