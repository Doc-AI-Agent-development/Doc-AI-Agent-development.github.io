# 불변식

어기면 **오류 없이 조용히 잘못 동작하는 규칙**들입니다. 각 항목에 위반 시 나타나는 증상을
함께 적습니다. 코드를 수정할 때 이 목록에 닿는 변경인지 확인하십시오.

| # | 규칙 | 위반 시 증상 |
|---|---|---|
| 1 | 작업공간 보관 필드 목록은 상태 모델과 작업공간 구조 양쪽에 같은 이름으로 존재해야 한다 | 교육 전환이 속성 오류로 전면 실패 |
| 2 | 턴 내 "복사본 최신 값 노출 규칙"과 "델타 병합 규칙"은 동일해야 한다 | 응답으로 보고한 내용과 저장된 상태가 어긋남 |
| 3 | 카드 답변은 계획으로 한 방향으로만 이동한다 — 계획 값을 카드에 되비추지 않는다 | 대화로 바꾼 값이 카드의 이전 답변으로 되돌아감 |
| 4 | 출처 교시 기록(수정 전 어느 교시에서 왔는지)은 승계 대응 정보를 뽑은 직후 비운다 | 다음 수정에서 이전 세대 번호가 섞여 근거가 잘못된 교시로 승계 |
| 5 | 유닛 위치 번호는 구성표의 주제 순서 기준이며, 생성·수정·병합 세 곳이 같은 규칙으로 독립 계산한다 | 부분 수정이 엉뚱한 유닛을 재작성 |
| 6 | 여백 상수(블록·세그먼트 간격)는 렌더러 셸 CSS와 같은 값을 유지하고, 페이지 예산은 가용 높이보다 여유를 남긴 값을 유지한다 | 페이지 넘침 또는 과도한 빈 공간 |
| 7 | 실측 모듈의 그림·기본 CSS는 렌더러 셸 CSS의 복제본이므로 함께 수정한다 | 캡션 있는 그림의 측정 오차로 페이지 넘침 |
| 8 | 생성 프롬프트 디렉터리의 접미 규칙 — 접미 없음이 가로형, `_portrait` 접미가 세로형 | 새 방향·프롬프트 추가 시 반대 방향 프롬프트를 수정하게 됨 |
| 9 | 도구 반환의 거부 접두 규약 — 정해진 접두("…불가:")로 시작해야 재시도가 허용된다 | 실패 반환("검색 실패:" 등)이 성공으로 기록되어 같은 인자 재호출이 차단됨 |
| 10 | 진행 단계 서술 상수는 추천 문구 에이전트가 직접 가져다 쓴다 | 단계 서술 변경 시 추천 칩 문구가 함께 변함 (의도 확인 필요) |
| 11 | 델타에 값 없음(None)을 싣지 않는다 — 산출물 필드는 키 존재 여부로, 시험 구성은 설정 플래그로 구분한다 | 이전 턴의 값이 의도치 않게 삭제됨 |
| 12 | 진행 시트는 항상 깊은 복사 후 수정한다 | 직렬화 중인 이전 턴 객체와 충돌 |
| 13 | 근거 번호는 저장소 크기 기준 순차 채번이므로 근거 목록은 추가만 한다 | 중간 삭제 시 번호 충돌 |
| 14 | 문서 이미지 목록과 이미지 판독 캐시는 프로세스 수명·파일 캐시다 — 원문 변경 시 재기동, 판독 프롬프트 개정 시 캐시 파일 정리가 필요하다 | 낡은 이미지 정보로 생성됨 |
| 15 | 새 교육 시작 시 상태 병합 순서는 초기화 → 보관 → 새 교육 순이어야 한다 | 새 교육의 계획이 초기화 값으로 덮여 모순 상태가 저장됨 |

각 규칙의 코드 위치는 해당 기능을 다루는 본문 페이지의 코드 참조 표를 따라가면
닿습니다 — 대응 페이지는 [디렉터리 구조](../concepts/code-map.md)에 정리되어 있습니다.
