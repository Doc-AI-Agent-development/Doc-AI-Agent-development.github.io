# 설계 원칙

교육자료 생성 탭의 구현이 일관되게 따르는 여덟 가지 원칙입니다. 각 원칙에 대해 규칙, 구현 방식,
위반 시 발생하는 문제를 설명합니다. 기능을 추가하거나 변경할 때는 해당 변경이 이 원칙과
충돌하지 않는지 먼저 확인해야 합니다.

## 1. LLM과 코드의 역할 분리

**발화 해석과 도구 선택은 LLM**이 수행하고, 코드는 **값 운반과 산술**(번호 부여, 합계,
재집계)만 수행합니다. 진행 단계 값이 상태에 저장되지만, 코드가 이 값으로 도구 사용을
제한하지 않습니다 — 담당자가 어느 단계에서든 이전 결정을 변경하면 LLM이 적절한 도구를
선택해 반영합니다.

코드에 발화 해석(키워드 분기)이나 단계 강제를 추가하면, 정의된 시나리오를 벗어나는
자연스러운 요청이 무시되는 회귀가 발생합니다.

## 2. 단일 소스 원칙

**동일한 값을 두 곳에 두지 않습니다**. [설정 질문 카드](../edu-material/settings.md)는 입력
수단이며, 답변은 [구성 계획](../edu-material/syllabus.md)으로 이동한 뒤 계획에서만
읽습니다. 분량 값은 교시의 쪽수 필드에만 존재합니다. 화면 표시,
완료 보고, 생성 입력이 모두 동일한 위치를 참조하므로 상호 불일치가 발생하지 않습니다.

**역방향 동기화**(계획 값을 카드에 반영)는 금지됩니다. 이를 추가하면 대화로 변경한 값이
카드의 이전 답변으로 되돌아가는 문제가 발생합니다.

## 3. 사실 기반 컨텍스트 구성

담당자에게 발화하는 LLM 호출에는 **전체 대화 이력**과 함께 코드가 산출한 현재 상태
사실(계획 전문, 근거 수량, 산출물 유무, 실측 결과)을 공급합니다. 내부 변환·판정 호출에는
대화 이력 대신 필요한 사실 전부를 공급합니다. 사실이 누락된 자리는 LLM이 추정으로
채우기 때문입니다.

대표적인 적용 예가 생성 완료 보고입니다. 지정 분량과 실제 분량의 차이와 그 방향(초과·
미달)을 코드가 확정해 사실 문장으로 공급하며, 실측과 다른 수치·방향으로 말하지 않도록
하는 지시가 사실과 함께 실립니다.

## 4. 결과 보고의 정확성

반영하지 못한 요청을 반영했다고 보고하지 않고, 생성하지 못한 것을 생성했다고 보고하지
않습니다. 도구는 실패 시 실패 사유를 사실 텍스트로 반환하고, 시스템 프롬프트와 도구
반환문에 **허위 완료 보고를 금지**하는 지시가 포함되어 있습니다. 시험 문항을 요청 수만큼
채우지 못하면 부족분을 그대로 보고하며, 코드가 임의로 문항을 생성해 채우지 않습니다.

## 5. 근거 기반 생성

교육자료의 내용은 수집된 근거(연간 교육계획, 법령, 첨부 문서, 사내 문서)에서 나옵니다.
**근거가 없으면 자료를 생성하지 않고** 해당 사실을 안내합니다. 표 참조가 필요한 시험 유형은
출제 재료(수강자에게 전달되는 자료 본문)에 표가 없으면 다른 유형으로 대체하고 그 사실을
보고합니다.

근거의 재료(첨부 목록, 제외 지정, 문서 수집 범위 설정)가 변경되면, 근거를 다시 수집하기
전까지 **생성이 차단됩니다**. 변경 전 재료로 수집한 근거로 자료가 생성되는 것을 막기 위한
게이트입니다.

## 6. 원문 발췌

근거 목록에 표시되는 발췌문은 LLM 요약이 아니라 **원문에서 그대로 추출한 문단**입니다.
발췌 내용의 사실 확인이 원문 대조로 성립하게 하기 위한 규칙입니다. 분량 제한이 필요한
경우에도 요약하지 않고, 키워드가 포함된 문단을 원문 그대로 선별하는 방식으로 줄입니다.

## 7. 실측 기반 페이지 구성

페이지 초과 여부는 계산으로 추정하지 않고, Chrome 브라우저로 **실제 렌더 높이를 측정**해
결정합니다. 내용을 먼저 완성한 뒤 페이지 분할을 실측으로 마지막에 결정하는 순서입니다.
완료 보고의 페이지 수도 실측값입니다.

Chrome이 없는 환경에서는 추정치로 대체 동작하지만, 이는 대비책이며 페이지 구성 품질이
저하됩니다. 배포 환경에 Chrome이 필요한 이유입니다.

## 8. 실패 처리와 대화 연속성

외부 자원(검색 엔진, 스토리지, 백엔드 API) 호출이 실패해도 **예외를 전파하지 않고**, 실패
사실을 안내 텍스트로 변환해 대화를 계속합니다. 검색 엔진에 연결할 수 없으면 그 사실이
LLM에 전달되고, LLM은 이를 담당자에게 알린 상태로 가능한 작업을 진행합니다.

실패를 무시하는 것과는 다릅니다. 실패는 반드시 사실로 노출되며, 세션이 중단되지 않을
뿐입니다.
