# 프롬프트와 설정 수정

프롬프트·설정을 고칠 때의 반영 방식과 주의점입니다. 프롬프트 파일의 위치 규약과 호출
전체 목록은 [LLM 호출 지도](../reference/llm-calls.md)가, 설정 키 목록은
[설정 항목](../reference/config.md)이 다룹니다.

## 반영 방식

| 수정 대상 | 반영 시점 |
|---|---|
| 프롬프트 파일(YAML) | 호출할 때마다 다시 읽음 — 저장하면 다음 호출부터, 재기동 불필요 |
| 파이썬 코드 | 서버 재기동 필요 |
| 환경 변수·`.env` | 서버 재기동 필요(기동 시점에 읽음) |
| 부서 위험 특성 표 | 서버 재기동 필요(기동 후 첫 사용 시 1회 읽어 보관) |

## LLM이 읽는 글의 네 층

모델의 판단을 바꾸려면 그 판단을 가르치는 글이 어느 층에 있는지부터 확인합니다.

1. **프롬프트 파일** — 행동 지침과 입력 틀 한 쌍.
2. **도구 설명** — 조회 도구는 도구별 Markdown 파일 본문이, 탭 내부 작업 도구는 함수의
   문서화 주석이 모델에 노출됩니다.
3. **구조화 출력 모델의 필드 설명** — 모델이 출력 칸을 채울 때 읽는 규칙입니다. 필드
   설명란에 쓴 글만 모델에 전달되며 일반 코드 주석은 전달되지 않습니다 — 주석만 달린
   필드는 모델이 뜻을 모른 채 값을 채웁니다.
4. **코드 상수로 관리되는 주입 문구** — 여러 프롬프트가 같은 규칙을 공유할 때 문구를
   상수 하나로 두고 각 프롬프트에 변수로 주입합니다(실시월 배정 규칙 등).

## 프롬프트와 수신 코드는 한 벌

프롬프트가 모델에 가르치는 출력 형태와, 그 출력을 받는 코드의 처리 규칙은 계약으로
맞물려 있습니다. 예를 들어 연간 계획의 편집 호출은 회차 수만 바꾸는 요구면 회차 시간
칸을 비워 두라고 가르치고, 받는 쪽 병합 규칙은 비워진 시간 칸을 "명시 없음"으로 읽어
연간 시간을 새 회차 수로 다시 나눕니다. 프롬프트만 바꾸고 병합 규칙을 그대로 두면
오류 없이 값이 어긋납니다. 출력 규칙을 바꾸는 프롬프트 수정은 **받는 코드의 처리와
같은 변경 단위로** 검토합니다.

같은 규칙을 서술하는 문장이 여러 프롬프트에 나뉘어 있을 수 있습니다. 실시월 배정 규칙
문구는 배정 호출과 편집 호출 두 프롬프트에 주입되고, 편집 호출의 프롬프트에는 그
규칙을 화면 사정에 맞게 조정하는 문장이 따로 있어 함께 확인해야 합니다. 문장을 교체할
때는 원래 문장이 지키고 있던 계약을 먼저 나열하고 새 문장이 전부 담는지 대조합니다 —
한 계약을 고치다 다른 계약이 문장과 함께 사라지는 실수가 흔합니다.

## 검증

모의 도구 모드의 LLM은 고정 응답을 돌려주므로, 프롬프트·필드 설명 변경의 효과는
유닛테스트로 검증되지 않습니다. 고친 경로를 실제 LLM 시나리오로 실행해
확인합니다([테스트](../testing.md)).

## 코드에 사는 업무 결정 값

다음 값들은 설정 파일이 아니라 코드 상수입니다. 환경에 따라 조절하는 손잡이가 아니라
**합의로 확정된 결정**이어서, 바꾸면 검증이 따라야 하므로 코드 변경으로 다룹니다.

- 일괄 생성의 운영 답안: 계획 범위, 시간 분할, 교육방법·평가방법, 실시월 공란,
  강사(교육시간과 회차 자체는 답안이 아니라 법정 교육시간·법정 주기가 정함)
- 실시월 배정 규칙 문구(연중 분산 방식의 월별 배정 상한은 설정 키로 조절 —
  [환경 변수](../reference/config.md))
- 설문 질문·보기·기본값의 정의([질문 에이전트](../annual-plan/question-agent.md))
- 저장 안내 문장 — 수정 안내와 조회 응대가 같은 문장을 공유

회차 내용 생성을 비롯한 연간 계획 LLM 호출의 동시 실행 상한과 제한 시간은 코드 상수가
아니라 기능별 설정 키입니다([환경 변수](../reference/config.md)의 기능별 LLM 호출 조절).
