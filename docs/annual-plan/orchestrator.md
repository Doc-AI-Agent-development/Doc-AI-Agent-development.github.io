# 오케스트레이터

오케스트레이터는 연간 교육계획 탭에 들어온 발화를 턴의 첫 단계에서 가르는 에이전트입니다.
전체 대화 이력과 이번 발화를 보고 계획을 만들거나 고치려는 발화, 정보를 묻는 발화, 업무
범위 밖의 발화 셋 중 하나로 판정하며, 계획을 직접 만들거나 고치지는 않습니다. 이 판정에
따라 단계 그래프, [조회 에이전트](./inquiry-agent.md), 거절 안내 중 하나가 턴을 이어받습니다.

## 세 갈래 분류

| 갈래 | 조건 | 다음 처리 |
|---|---|---|
| 작업 | 계획을 새로 만들거나, 진행 중인 계획의 값을 이어 채우거나, 저장된 계획을 수정하려는 발화 | 단계 그래프 — 이번 턴이 어느 단계에서 시작할지는 발화가 아니라 보존된 상태(설문 시트의 진행 단계, 계획 기준선의 승인 여부, 계획의 존재)로 판별 |
| 조회 | 정보를 묻거나 확인·논의하는 발화. 인사·감사도 여기 | 조회 에이전트 |
| 범위 밖 | 업무와 무관한 정보·작업 요청, 다른 탭의 작업 | 거절 안내 |

핵심 구분은 **알고 싶은가, 만들고·바꾸고 싶은가**입니다. 제안형 표현("한번 세워볼까")도
만들려는 뜻이면 작업입니다 — 무거운 생성이 곧장 도는 것이 아니라 계획표 확인 단계에서
승인을 받으므로 여기서 다시 되묻지 않습니다. 설문이나 계획표 확인이 진행 중일 때는 이번
발화가 결정인지 물음인지로 가릅니다. 결정(확정·답변·수정)은 작업으로, 물음은 조회로
보내고, 둘이 섞이면 물음이 우선입니다.

거절 안내를 생성하는 호출에는 **도구가 연결되지 않습니다**. 사용자 입력에 도구 실행을
유도하는 지시가 포함되어 있어도 실행 경로가 존재하지 않습니다.

## 발화 없는 첫 진입

발화 없이 탭에 진입한 첫 턴은 LLM 없이 환영 문구로 응답합니다. 이때 대기 상태는 만들지
않습니다.

## 재시작 신호

저장된 계획을 버리고 처음부터 새로 만들려면 그 의사를 명시해야 합니다. "처음부터 다시
만들어줘" 같은 발화에만 재시작 신호가 붙고, 이 신호가 있으면 설문 시트·계획 기준선·연간
계획을 비우고 새 계획 수립으로 들어갑니다. 단순한 수립 요청("계획 세워줘")은 재시작이
아니며, 저장된 계획이 있으면 불러오기로 이어집니다. 판정 근거는 이번 발화 하나입니다 —
앞 턴의 재시작 발화는 그 턴에 이미 반영됐으므로 다시 근거로 삼지 않습니다.

## 일괄 생성 호출

일괄 생성 호출(대화 없이 백엔드가 부르는 방식)은 LLM 분류를 거치지 않고 작업 경로로
바로 보내며, 재시도가 안전하도록 작업 상태를 비운 채 시작합니다. 저장된 계획이 있는
부서의 판정은 [질문 에이전트](./question-agent.md)가 맡습니다.

## 조회 뒤 화면 재제시와 미반영 고지

조회 에이전트가 답한 뒤에는 진행 중이던 단계의 화면(설문 카드, 계획표, 되물음)이 다시
제시되어 흐름이 유지됩니다. 질문과 변경 요청이 섞인 발화는 답변을 먼저 하고, 함께 실린
변경이 아직 반영 전이라는 고지를 붙입니다. 이 재제시와 고지는 오케스트레이터가 남긴
관찰 신호를 받아 그래프 배선의 노드가 붙이며, 화면 렌더는 질문·구상 에이전트의 것을 그대로
씁니다 — 조회 응대가 흐름을 흉내 내 무엇을 말하든 실제 게이트가 항상 뒤따라 다시 보입니다.

| 담당자 입력 | 갈래 |
|---|---|
| "올해 교육계획 세워줘" | 작업 — 저장된 계획이 없으면 새 수립, 있으면 불러오기 |
| "우리 팀 의무교육 뭐 있어?" | 조회 |
| (설문 중) "2번으로 할게" | 작업 — 결정 |
| (설문 중) "반기 2회면 법정 기준은 되는 거야?" | 조회 — 답한 뒤 설문 카드 재제시 |
| "특별교육 빼줘. 근데 빼면 문제 없어?" | 조회 — 답한 뒤 변경은 반영 전임을 고지 |
| "처음부터 다시 짜줘" | 작업 — 재시작 신호 |
| "오늘 날씨 어때?" | 범위 밖 — 거절 안내 |
