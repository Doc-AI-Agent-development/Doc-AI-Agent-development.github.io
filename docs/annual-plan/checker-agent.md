# 요건 검사 에이전트

요건 검사 에이전트는 완성된 계획을 검토해 확인이 필요한 문제를 알리는 에이전트입니다.
**어떤 결과도 진행을 차단하지 않습니다**. 검사는 담당자의 판단 재료를 주는 것이고, 계획을
고칠지는 담당자가 정합니다.

검사 표시는 두 층으로 나뉩니다. 계산으로 확정되는 사실은 상태 파생 경고가, 대화 맥락이
있어야 판단할 수 있는 문제는 LLM 검토가 맡습니다.

## 상태 파생 경고

[구상 에이전트](./plan-table-agent.md)에서 다룬 네 가지 경고(법정 교육 제외, 회차 미달,
시간 미달·미정, 기준 미상)는 계획 상태에서 파생되어 검사 결과에도 같은 판정으로
표시됩니다. 상태가 유지되는 동안 계속 보이고, 값을 되돌리면 사라집니다.

## LLM 검토

LLM 검토는 계획표, 법정 기준, 이번 턴에 바뀐 값, 그리고 대화 이력 전체를 읽고 **담당자가
의도하지 않았을 문제만** 짚습니다.

- **직접 지시한 변경은 다시 지적하지 않습니다.** 담당자가 법정 기준보다 낮은 시간을 알고
  지시했다면 그 값은 본인의 결정입니다. 미달 사실은 상태 파생 경고가 이미 보여주므로,
  검토가 같은 내용을 반복하지 않습니다. 이 구분이 LLM 검토를 두는 이유입니다: 계산은
  기준 미달만 알 수 있지만, 검토는 대화를 읽고 그것이 본인의 결정인지 놓친 문제인지
  구분합니다.
- **이미 표시된 경고를 반복하지 않습니다.** 상태 파생 경고에 있는 교육과 사실은 검토
  대상에서 제외됩니다.
- **확실한 것만, 없으면 침묵합니다.** 지시의 파급으로 다른 값이 함께 어긋난 경우, 대화의
  요구와 계획표가 서로 다른 경우, 실시월이 무리하게 몰리거나 겹치는 경우처럼 계획표와
  대화에서 확인되는 사실만 소수로 짚고, 짚을 것이 없으면 문제 없음으로 보고합니다.
  검토 호출이 실패해도 침묵합니다. 검토는 부가 기능이라 진행을 깨지 않습니다.

## 검사 시점

검토는 세 시점에 수행됩니다. 계획표가 처음 제시될 때, 생성이 끝난 직후, 그리고 생성
후 값 수정이 반영된 턴입니다. 값이 바뀌지 않은 턴에는 재검사하지 않습니다.

## 결과의 형태

<div class="example-block">

\[요건 검사] 계획을 검토했습니다.
⚠️ 법정 필수 교육 「특별 안전작업 교육」이(가) 계획에서 제외되어 있습니다. 법정 요건을
충족하지 못할 수 있으며, 제외된 교육은 요건 검사 대상에서도 빠집니다.
이대로 진행할 수 있고, 조정하실 값이 있으면 말씀해 주세요.

</div>

응답 산출물의 검사 결과 데이터에는 짚은 항목이 경고 수준으로 담기며, 검사 결과가 진행을
막는 상태 값은 없습니다.

이 에이전트가 맡는 기능을 고치려면 [유지보수의 요건 검사 에이전트](../maintenance/annual-plan/checker-agent.md)을 보십시오.
