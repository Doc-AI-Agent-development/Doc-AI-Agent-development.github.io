# 첨부 자료 처리

**첨부 자료**는 담당자가 대화에 업로드한 문서입니다. **교육 진입 전이든 작업 중이든 어느
턴에나 올릴 수 있으며**, 올라온 첨부는 **요지 파악과 근거 활용**의 두 단계로 처리됩니다.
첨부 기반으로 교육에 진입하는 경우에는 구성 계획 수립의 재료로도
사용됩니다([교육 선택과 진입](./course-entry.md) 참조).

## 첨부 수신

화면은 세션에 업로드된 전체 파일 목록을 매 턴 제공합니다. 시스템은 이미 처리한 파일
목록과 비교해 **신규 첨부만 처리**합니다. 파일 목록 계약은 레퍼런스의 API 페이지에서
다룹니다 — [API 계약](../reference/api.md) 참조.

지원 형식은 PDF와 Word(docx), PowerPoint(pptx), 그리고 txt·md·csv·log·html 텍스트
계열입니다. 구형 형식(doc·ppt)을 포함해 지원하지 않는 형식, 웹 URL, 문서에 포함되지
않은 단독 이미지는 **처리할 수 없으며** 그 사실을 안내합니다.

## 요지 파악

신규 첨부는 내용을 읽어 파일별 요지를 추출·보관합니다. 요지는 첨부를 어느 교시에 쓸지
판단하는 데 쓰이고, 첨부를 인지했다는 사실을 담당자에게 안내할 때도 사용됩니다.

- 동일한 내용의 파일이 다시 업로드되면 **보관된 요지를 재사용**합니다(내용 해시 비교).
- 파일 읽기나 요지 추출이 일시적 사유(연결 오류 등)로 실패하면 다음 턴에 다시
  시도합니다. 형식 미지원 같은 **영구 사유는 재시도하지 않습니다**.
- 복수 파일의 요지 추출은 동시 호출 상한 내에서 병렬로 처리됩니다.

## 이미지 추출

생성 준비 단계에서 첨부 문서에 포함된 이미지를 추출해 **서버 로컬 캐시**에 보관합니다.
추출된 이미지를 공유 스토리지에 두지 않는 이유는, 화면이 스토리지의 세션 폴더 전체를
첨부 목록으로 다시 제공하기 때문입니다 — 공유 위치에 두면 추출 이미지가 새 첨부로
잘못 인식됩니다. 캐시는 세션 삭제 시 함께 정리되며, 오래된 캐시는 서비스 기동 시
정리됩니다.

## 근거 활용

첨부는 근거 수집 시 **근거의 한 종류로 편입**됩니다.

- **교시 귀속** — 담당자가 용도로 교시를 지정한 파일은 그 지정을 그대로 따릅니다.
  지정이 없는 파일은 LLM이 첨부 내용과 교시 구성을 보고 배정하며, 첨부 기반 진입의 주
  근거 파일은 전 교시에 적용됩니다.
- **편입·제외** — 특정 첨부를 근거에 추가하거나 제외할 수 있으며, 용도("이 파일은 사고
  사례로")를 함께 지정할 수 있습니다.
- **문서 수집 범위 지정** — "첨부한 문서만으로 만들어 줘"라고 지정하면 사내 문서 검색 없이
  첨부만으로 근거를 구성합니다. [근거 수집](./evidence.md)에서 다룹니다.

첨부 목록·제외 지정·문서 수집 범위가 변경되면 **근거를 다시 수집하기 전까지** 생성이
차단됩니다([설계 원칙](../maintenance/design-principles.md)의 근거 기반 생성 참조).
