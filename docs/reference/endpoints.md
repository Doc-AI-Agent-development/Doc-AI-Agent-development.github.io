# 엔드포인트

이 서비스가 외부에 제공하는 HTTP 인터페이스는 아홉 개입니다. 이 페이지는 각각을 언제
어떻게 부르는지 다룹니다. 요청·응답의 공통 구조와 컨텍스트 키, 오류 코드는
[API 계약](./api.md)에 있습니다.

작업이 실제로 일어나는 창구는 `POST /agent/invoke` 하나뿐입니다. 계획 수립이든 교육자료
생성이든 요약이든 모두 이 창구로 들어오고, 요청에 실린 탭 식별자로 갈립니다. 원문자료
업로드 창구는 대화가 아니라 사내 문서 코퍼스에 문서를 등록하는 별도 작업이며, 나머지
일곱은 세션 관리와 상태 조회, 알림 접수입니다.

| 메서드·경로 | 성격 |
|---|---|
| `POST /agent/invoke` | 작업 |
| `GET /agent/progress/{thread_id}` | 상태 조회 |
| `POST /agent/threads/{thread_id}/cancel` | 세션 관리 |
| `DELETE /agent/threads/{thread_id}` | 세션 관리 |
| `GET /tabs` | 조회 |
| `GET /health` | 조회 |
| `POST /agent/documents/upload` | 원문자료 등록 |
| `POST /agent/documents/uploaded` · `deleted` | 알림 접수 |

## POST /agent/invoke

담당자의 발화 한 번을 처리합니다. 응답이 나올 때까지 한 번에 반환하며, 중간 상태를
흘려보내지 않습니다. 처리 중 진행 상황이 필요하면 진행 상태 조회를 함께 씁니다.

필수 값은 둘입니다. 세션 식별자(`thread_id`)와 대상 탭(`context.tab`)이며, 둘 중 하나라도
없으면 입력 오류로 응답합니다. 탭을 임의로 고르는 폴백은 없습니다.

발화 없이 부르면 탭 첫 진입으로 보고 시작 안내를 돌려줍니다.

같은 세션 식별자로 다시 부르면 이전 대화가 이어집니다. 요청이 나르는 것은 세션 식별자와
컨텍스트뿐이고, 누적된 상태는 서버가 복원합니다.

## GET /agent/progress/&#123;thread_id&#125;

한 턴이 처리되는 동안 무엇을 하고 있는지 조회합니다. 화면의 기존 폴링 주기에 이 조회를
하나 더하는 방식으로 쓰며, 별도의 연결 유지가 필요 없습니다.

```json
{"success": true,
 "data": {"thread_id": "t-0101", "tab": "annual_plan", "running": true,
          "node": "plan_writer", "label": "교육별 상세 내용을 생성하는 중",
          "status": "", "detail": {"started": 9, "done": 4},
          "updated_at": "…"},
 "meta": {}}
```

- `label`은 단계마다 정해진 문구로 **항상 있습니다**.
- `status`는 담당자의 발화에서 뽑은 한 줄로 **있을 때만** 채워집니다. 화면은 `status`가
  있으면 그것을, 없으면 `label`을 표시합니다. 오래 걸리는 단계에 들어가면 발화 기반 문구는
  낡은 정보가 되므로 지워집니다.
- `detail`은 과정별 생성 진행 집계입니다. 해당 단계가 아니면 비어 있습니다.
- `node`는 내부 단계 이름입니다. 표시에는 `label`·`status`를 쓰고 이 값에 기대지 마십시오.

턴이 끝나면 `running`이 거짓이 되고 마지막 스냅샷이 남습니다. 한 번도 실행되지 않은
세션이나 서비스 재시작 뒤에는 `running` 거짓만 담긴 최소 응답이 옵니다. 오류가 아닙니다.

## POST /agent/threads/&#123;thread_id&#125;/cancel

진행 중인 턴을 실제로 멈춥니다.

화면에서 취소를 눌러 HTTP 연결이 끊겨도 **서버 처리는 계속됩니다.** 취소를 서버까지
전하려면 이 창구를 호출해야 합니다. 취소된 턴은 그 턴이 남긴 기록까지 되돌려져 대화에서
사라지므로, 같은 말을 다시 해도 안전합니다. 원래의 작업 요청은 취소 오류 코드로 응답합니다.

```json
{"success": true, "data": {"thread_id": "t-0101", "cancelled": false},
 "meta": {"thread_id": "t-0101"}}
```

진행 중인 턴이 없으면 아무 일도 하지 않고 `cancelled` 거짓으로 성공 응답합니다. 여러 번
불러도 안전합니다. 이미 끝난 턴은 되돌리지 않습니다. 완료보다 늦게 도착한 취소는 무효이며
호출측은 `cancelled` 값으로 구분합니다.

같은 세션에 새 요청이 들어와도 같은 장치가 동작합니다. 돌던 턴을 취소·되돌리고 새 요청을
처리하므로, 한 세션에서 처리 중인 턴은 항상 하나입니다.

## DELETE /agent/threads/&#123;thread_id&#125;

세션 하나를 지웁니다. 대화 이력, 진행 상태, 그 세션의 산출물이 함께 사라지며
**복구할 수 없습니다.** 세션의 첨부 이미지 캐시도 함께 정리됩니다.

용도는 호출측이 사용자별 대화 목록을 관리하다 상한을 넘겼을 때 오래된 세션을 정리하는
것입니다. 세션 목록과 사용자 매핑은 호출측이 소유하며, 이 서비스는 세션 식별자만 압니다.
목록을 돌려주는 창구는 없습니다.

진행 중인 턴이 있으면 먼저 끊고 지웁니다. 없는 세션을 지우려 하면 성공 대신
`STATE_NOT_FOUND` 오류로 응답합니다. 재시도로 이미 지워진 경우라면 호출측이 성공으로
간주해도 무방합니다.

## GET /tabs

어떤 탭이 있고 각각 쓸 수 있는 상태인지 돌려줍니다. 화면이 탭을 보여줄지 판단하는 근거로
씁니다.

```json
{"annual_plan": {"label": "연간 교육계획 수립", "ready": true},
 "exam_generation": {"label": "시험 문제 생성·채점", "ready": false}}
```

`ready`가 거짓인 탭을 호출하면 오류가 아니라 준비 중 안내 발화로 응답합니다.

## GET /health

서비스가 떠 있는지 확인합니다. 배포·감시에서 씁니다.

```json
{"status": "ok", "service": "backend_ai", "environment": "development", "model": "…"}
```

## POST /agent/documents/upload

원문 문서 파일을 받아 사내 문서 코퍼스에 등록합니다. 원문자료 관리 화면(BFF)이 부르는
창구이며, 담당자가 대화에 첨부하는 파일과는 다른 경로입니다.

요청은 multipart 형식입니다. 파일이 필수이고, 저장 카테고리·외부 문서 식별자·원본
파일명 보정은 선택입니다. 서비스는 파일을 텍스트 문서로 변환해 저장하고, 요약을 만들고,
검색 색인에 넣는 순서로 처리하며 원본 바이트는 보관하지 않습니다 — 원본 보관은 호출측
소관입니다.

```json
{"success": true,
 "data": {"accepted": true, "path": "…/content.md", "images": 3,
          "summary": true, "indexed": true},
 "meta": {}}
```

`summary`와 `indexed`는 요약과 색인이 실제로 반영됐는지의 값입니다. 둘 중 하나가
실패해도 등록 자체는 성공으로 응답하며, 그 경우 사유가 `summary_error`·`index_error`로
함께 실립니다. 지원하지 않는 형식이거나 변환에 실패하면 각각의 오류 코드로 응답합니다.

## POST /agent/documents/uploaded · deleted

관리자 문서함에 원문 문서가 올라오거나 지워졌을 때 백엔드가 알려 주는 창구입니다. 재업로드
같은 버전 교체도 업로드 알림을 다시 부릅니다.

**현재는 접수만 합니다.** 검색 색인은 별도 배치로 갱신되며, 이 호출이 재색인을 일으키지
않습니다. 응답의 `reindexed`가 항상 거짓인 것은 그 사실을 숨기지 않기 위해서입니다. 나중에
재색인이 이 자리에 붙어도 **호출 방법과 응답 형태는 그대로**입니다.

```json
{"success": true,
 "data": {"event": "uploaded", "doc_id": "D-1", "accepted": true, "reindexed": false},
 "meta": {}}
```

`doc_id`는 필수이며 비어 있으면 입력 오류로 응답합니다. 나머지 필드(원본 파일명, 변환문서
경로, 버전 표기)는 선택이며 기록에만 씁니다.

이 창구는 담당자가 대화에 첨부하는 파일이나 원문자료 업로드 창구와는 **다른 경로**입니다.
채팅 첨부는 요청의 컨텍스트로 전달되고, 원문자료 업로드는 파일을 직접 받아 등록합니다.

## 응답 형식의 예외

작업과 세션 관리 창구는 성공·실패와 관계없이 같은 구조의 봉투로 응답합니다. 다만
`GET /tabs`와 `GET /health` 둘은 봉투 없이 값만 돌려줍니다. 화면이 이 둘을 부를 때는
`success` 필드를 찾지 마십시오.
