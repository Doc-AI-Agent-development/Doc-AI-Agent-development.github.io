# 외부 의존

AI 서비스가 의존하는 외부 자원 다섯 가지와, 각 자원에 접근할 수 없을 때의 동작을
정리합니다. 외부 호출 실패는 **예외로 전파되지 않고 안내 사실로 변환**되는 것이 기본
원칙입니다 — 실패 사실이 담당자 안내에 포함된 채 대화가 계속됩니다.

## 백엔드 교육 데이터 API

교육과정, 부서, 공통코드, 연간 교육계획, 교육 실적은 백엔드가 제공하는 조회 API로만
접근합니다. 서비스가 **DB에 직접 접속하는 경로는 없습니다**. 조회는 엔드포인트별
메서드가 1:1로 대응하는 단일 클라이언트가 담당하며, 조인·정렬은 백엔드가 수행한 결과를
받습니다.

**실패 시 동작** — 이 클라이언트에는 **폴백이 없습니다**. 연결 실패·오류 응답은 예외로
반환되고, 호출하는 쪽이 각자 대체 동작을 결정합니다. 예를 들어 연간 교육계획 행 조회에
실패하면 교육과정 정보만으로 계획 재료를 구성하고, 후보 목록 조회에 실패하면 다시
시도해 달라는 안내가 나갑니다. 조회는 성공했으나 결과가 없는 경우는 등록된 계획이
없다는 안내로 구분됩니다.

## 사내 문서 검색 엔진

사내 문서는 검색 엔진(OpenSearch)의 **키워드 기반**(BM25) 색인으로 검색합니다. 색인 단위는
문서 하나이며, 제목·목차·요약·본문 필드에 가중치를 둔 질의를 사용합니다. 임베딩 기반
**의미 검색은 사용하지 않습니다** — 관련 설정도 두지 않습니다.

**코퍼스 갱신 절차** — 색인이 갱신되는 경로는 둘입니다. 전체 색인은 **오프라인 배치**로
다시 만들고, 문서 한 건은 원문자료 업로드 창구가 등록하면서 그 문서만 색인에 넣습니다
([엔드포인트](./endpoints.md)). 문서함 변경 알림 API는 현재 수신만 하는 스텁이며
**재색인을 수행하지 않습니다**. 또한 문서 이미지 목록과 이미지 내용 판독 결과는 프로세스
수명 캐시와 파일 캐시에 보관되므로, 문서 원문이 바뀌면 배치 색인 후 서비스 재기동이
필요합니다.

**실패 시 동작** — 검색 엔진에 연결할 수 없으면 근거 수집은 계획·법령·첨부만으로
진행되고, 검색 불가 사실이 담당자 안내에 포함됩니다. 대화 중 문서 검색 도구는 실패
사유를 안내문으로 반환합니다.

## 파일 스토리지

대화 첨부 파일의 원본은 스토리지 서비스에 있으며, AI 서비스는 **조회 전용으로
사용**합니다 — 파일 목록 조회와 파일 인출 두 가지 호출만 존재하고, 쓰기·삭제는 하지
않습니다. 대화 첨부 파일의 바이트를 직접 수신하는 경로는 없습니다. 원문자료 업로드
창구가 파일을 직접 받는 것은 사내 문서 코퍼스 등록이며 대화 첨부와는 별개 경로입니다.

**실패 시 동작** — 인출 실패(연결 오류, 파일 없음)는 예외가 아니라 사유 문구로
반환되어, 해당 파일이 읽히지 않았다는 사실이 대화에 전달됩니다.

## LLM 서비스

LLM은 Azure OpenAI를 사용합니다. 호출 파라미터는 클라이언트 구성 한 곳에 고정되어
있고, 구조화 출력이 필요한 호출은 출력 스키마를 강제하는 방식으로 실행됩니다. 자격
정보가 설정되지 않은 상태에서 호출이 시도되면 즉시 오류가 발생합니다. 모든 호출의 토큰
사용량이 호출 단위로 로그 파일에 기록됩니다.

## Chrome

페이지 구성의 렌더 높이 실측은 Chrome을 헤드리스 모드로 실행해 수행합니다. 실행 파일은
시스템 경로와 표준 설치 위치에서 탐색됩니다.

**부재 시 동작** — Chrome이 없으면 오류 없이 **추정치 기반으로 동작**하지만 페이지 구성
품질이 저하됩니다 — 유닛 하나짜리 페이지가 늘어나거나 내용이 페이지를 넘치는 증상이
나타납니다. 배포 환경에는 Chrome 설치가 필요합니다.
