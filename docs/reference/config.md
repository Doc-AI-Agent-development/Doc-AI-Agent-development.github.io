# 환경 변수

서비스 동작을 조절하는 설정 키의 목록입니다. 모든 키는 **환경 변수로 재정의**할 수 있으며,
정의와 기본값은 **설정 모듈**(`src/core/config.py`)이 기준입니다. 이 페이지는 키의 역할과
쓰이는 자리만 안내하고 **값은 싣지 않습니다** — 값은 코드를 확인하십시오.

## 외부 서비스 접속

배포 환경에서 설정해야 하는 접속 정보입니다. 각 서비스의 역할과 실패 시 동작은
[외부 의존](./external-services.md)에서 다룹니다.

| 키 | 역할 |
|---|---|
| `backend_api_base` | 백엔드 교육 데이터 API 주소 — 교육과정·연간 계획·실적 조회에 사용 |
| `storage_api_base` | 파일 스토리지 서비스 주소 — 첨부 파일 목록·원문 인출에 사용 |
| `opensearch_host` / `opensearch_port` / `opensearch_index` | 사내 문서 검색 엔진 접속 정보와 색인 이름 |
| `azure_openai_*` | LLM 자격·배포 구성 — 설정 없이 LLM 호출이 시도되면 즉시 오류 |

## 문서 검색과 수집

교시별 근거를 모으는 [문서 수집](../edu-material/evidence.md)과 오프라인 배치 색인에서
쓰입니다.

| 키 | 역할 |
|---|---|
| `doc_search_top_k` | 검색 질의 하나가 가져오는 후보 문서 수 상한 |
| `doc_select_max` | 교시 하나에 채택하는 근거 문서 수 상한 — LLM이 후보를 검토해 최대 이 수까지 고름 |
| `candidate_review_chars` | 요약이 없는 후보 문서를 선별할 때, 검색에 걸린 대목 주변에서 읽는 본문 분량 |
| `conversation_evidence_max_chars` | 담당자가 대화 중 문서 원문을 요청할 때 한 턴에 실어 오는 본문 분량 상한 — 대화 턴은 이력·근거 목록을 이미 싣고 있어 생성 호출보다 여유가 적음. 넘으면 긴 문서부터 키워드 대목 주변으로 좁힘 |
| `document_source_dir` | 사내 문서 원문 파일의 루트 폴더 — 원문 인출과 배치 색인의 원천 |
| `doc_index_body_max_chars` | 배치 색인이 문서 하나의 본문을 색인에 담는 분량 상한 — 오염되었거나 비정상적으로 큰 문서가 색인 품질을 해치는 것을 막는 방어 |
| `doc_summary_crosswalk` | 배치 색인과 업로드 등록이 본문 문서와 큐레이션 요약 파일을 잇는 대응표 파일 경로 — 대응이 없는 문서는 본문 도입부로 요약을 대신함 |
| `large_doc_chars` | 원문 인출 시 이 길이를 넘는 문서를 대형으로 표시해 통째 주입 대신 부분 참조로 전환하는 기준 |
| `doc_upload_default_category` | 원문자료 업로드 창구가 카테고리를 받지 않았을 때 문서를 저장하는 하위 경로 |

## 교육자료 생성

| 키 | 역할 |
|---|---|
| `evidence_supply_max_chars` | 교육자료·시험 생성의 LLM 입력에 싣는 채택 문서 전문의 합계 상한 — 기준은 전문 공급이며, 합계가 상한을 넘을 때만 각 문서를 검색 키워드 대목 주변 창으로 좁혀 공급 |
| `generation_stage_dump_dir` | 진단용 — 경로를 지정하면 교시별 생성 중간 결과(전개 구조·유닛·정리 결과)가 파일로 남음. 기본은 비활성. [테스트](../testing.md) 참조 |

## 첨부 처리

| 키 | 역할 |
|---|---|
| `upload_summary_concurrency` | 첨부 요지 추출의 동시 LLM 호출 상한 — 파일 수만큼 호출이 한꺼번에 나가 게이트웨이가 몰림 거절하는 것을 막음. 입력을 자르는 값이 아님 |
| `upload_image_dir` | 첨부 문서에서 추출한 이미지의 서버 로컬 캐시 폴더 — [첨부 자료 처리](../edu-material/uploads.md)의 이미지 추출 참조 |

## 연간 계획 생성

| 키 | 역할 |
|---|---|
| `dept_risk_profiles_path` | 부서 위험 특성 표(사람이 편집하는 마크다운 파일) 경로. 연간 계획의 교육 내용에 부서 맞춤을 반영하는 재료로, 원천 DB 테이블이 없어 이 파일이 정본 |
| `annual_auto_hours` / `annual_auto_sessions` | 일괄 생성이 쓰는 과정별 연간 교육시간과 회차 수 |
| `annual_month_assign_cap` | 실시월을 연중 분산으로 배정할 때 한 달에 배정하는 교육 수 상한 |

### 기능별 LLM 호출 조절

연간 계획의 LLM 호출 여섯 기능은 모두 대상 수만큼 같은 호출을 반복합니다. 기능마다 대상
수와 호출 무게가 달라 동시 실행 수와 제한 시간을 따로 조절합니다. 동시 실행 수는 한꺼번에
뜨는 호출 개수의 상한이고, 제한 시간은 호출 한 건이 그 시간을 넘기면 그 건만 끊는 값입니다.

| 키 앞머리 | 조절 대상 |
|---|---|
| `annual_split_*` | 회차 주제 배분 — 다회차 과정마다 한 번 |
| `annual_topic_*` | 학습 주제 추출 — 목차 형식이 아닌 학습 내용을 가진 과정마다 한 번 |
| `annual_resplit_*` | 재배분 — 회차 수가 바뀌어 배분이 사라진 과정마다 한 번 |
| `annual_generate_*` | 첫 생성 — 회차 행마다 한 번. 호출 한 건이 가장 무겁습니다 |
| `annual_partial_*` | 부분 생성 — 새로 생긴 회차·과정 행마다 한 번 |
| `annual_revise_*` | 내용 재작성 — 수정 요청이 지목한 회차마다 한 번 |

각 앞머리에 `_concurrency`(동시 실행 수)와 `_timeout_seconds`(제한 시간)가 붙습니다.

## 실행 모드 — 테스트·로컬 개발용

모의 모드는 **유닛테스트**와 **외부 자원 없는 로컬 개발**에서 씁니다. 운영 배포에서는 두
키 모두 실제 모드여야 합니다. 사용 방법은 [개발 환경과
실행](../maintenance/dev-setup.md)과 [테스트](../testing.md)에서 다룹니다.

| 키 | 역할 |
|---|---|
| `tool_mode` | 실제 자원 사용 / 모의 도구(LLM 포함 전체) — 모의는 유닛테스트와, LLM·검색·백엔드 없이 서버 구조를 확인하는 기동에 사용 |
| `data_backend` | 교육 데이터 조회 — API 사용 / 빈 결과 반환 — 빈 결과 모드는 백엔드 없이 개발·테스트할 때 사용 |

## 저장·기록과 환경 표기

| 키 | 역할 |
|---|---|
| `agent_state_db` | 체크포인트 DB(sqlite) 파일 경로 — 세션 상태가 저장되는 곳. [상태와 세션](../concepts/state.md) 참조 |
| `token_usage_log` | LLM 호출별 토큰 사용량이 기록되는 로그 파일 경로 — 비용·호출 폭주 확인용 |
| `log_level` | 서비스 로그의 출력 수준 |
| `environment` | 상태 확인 응답에 표기되는 환경 이름 — 동작에는 영향을 주지 않음 |

## 선언만 있고 읽는 코드가 없는 키

다음 키는 설정에 선언되어 있으나 **현재 읽는 코드가 없습니다**. 새 기능을 이 키에 기대어
설계하기 전에 읽는 코드가 없다는 사실을 확인하십시오.

| 키 | 비고 |
|---|---|
| `vision_images_per_doc_max` | 읽는 코드 없음 |
| `doc_queries_per_module_max` | 읽는 코드 없음 |
| `component_asset_base` | 읽는 함수는 남아 있으나 그 함수를 부르는 코드가 없음 |
